Strategy review · greyin platform

What LinkedIn, Toptal, and Topmate already figured out

Greyin's five pillars benchmarked against six platforms that solve adjacent problems — professional networking, job search, salary transparency, freelance marketplaces, curated expert vetting, and paid 1:1 mentorship — with recommendations scoped against what's already built, not a wishlist.

22 Aug 2026 6 platforms benchmarked 5 pillars + hub

Where Greyin already leads: nothing benchmarked here has an equivalent to the Greyin Score — a single, cross-platform, peer-and-outcome-derived trust number spanning four independent products. LinkedIn's endorsements are self-selected and unverified; Toptal's vetting is a one-time gate, not a running score; nobody else has it continuously updating from real delivered work.

Where the gaps are: peer-to-peer trust signals (endorsements, written recommendations), salary transparency, company reviews, and turning the passive "mentor" flag into an actual bookable, paid product — Topmate's entire business model sitting one inch away from a badge Greyin already has.

How to read the "builds on" note under each recommendation: every one is scoped against infrastructure that already exists in this codebase (the follow graph, the escrow/payout rails, the LLM provider plumbing, the GreyMatters CMS) — none of these are green-field builds.

Recommendations

ranked by leverage · existing-infra reuse first

Highest leverage — turns an existing flag into a real product

Bookable, paid mentor sessions Reuses payment + messaging rails

Inspired by Topmate

profiles.is_mentor exists today purely as a directory badge — there's no way to actually book or pay a mentor for time. Add a mentor availability/rate table and a session-booking flow that reuses FreeAgent's already-working Razorpay escrow (a session is functionally a zero-delivery-days "gig") and the shared direct_messages/notifications tables for scheduling coordination.

FreeAgent's gig_orders escrow + payout flow, the shared conversations table, the existing notifications pipeline.

Peer trust signals — the follow graph makes these newly cheap to build

Skill endorsements One new table + the follow graph

Inspired by LinkedIn

A follower can endorse a specific skill on someone's profile — lightweight, one click, no free text. This is the platform's own "not a self-reported resume" thesis made literal: skills become peer-attested instead of self-listed, and endorsement counts can feed skill-level detail into the Greyin Score rather than only a single aggregate number.

user_follows (053_activity_feed.sql) as the eligibility gate — only people who follow you, or worked with you on a shared StackEdge project/FreeAgent order, can endorse.

Written recommendations Same follow-graph pattern, richer content

Inspired by LinkedIn

A short, structured testimonial from someone who actually worked with you — displayed on your profile alongside the Greyin Score. Given the platform's own positioning ("senior talent keeps getting filtered out by keyword-matching software"), a real qualitative peer testimonial is exactly the kind of signal an ATS bot can't fake and a recruiter can't ignore.

Same eligibility model as endorsements above; the existing AI quality-sweep infrastructure (llm_providers/llm_feature_flags) could optionally flag spammy/low-effort recommendations the same way it already screens posts and delivery quality.

Trust & transparency — genuinely new data Greyin is uniquely positioned to have

Salary benchmarking by role and experience Schema already has the raw data

Inspired by Glassdoor

jobs.salary_min/salary_max/salary_disclosed already exists per listing but is never aggregated. A "median senior Staff Engineer salary across the ecosystem" report, computed only from Verified Expert postings, would be real, sourced data most job boards can't claim — self-reported salary data is Glassdoor's actual weak point, and Greyin's data isn't self-reported.

A read-only aggregate view over jobs, same convention as platform_search_index/activity_feed — no new write path needed.

Verified-reviewer company reviews New table, narrow scope

Inspired by Glassdoor

Glassdoor's biggest known weakness is anonymous-anyone reviews with no proof the reviewer ever worked there. Scope this narrower and more defensibly: only a candidate who actually applied (or was hired) via ExpertEdge can review that company — smaller volume than Glassdoor, but every review is provably real, which is a stronger trust claim than Glassdoor can make.

applications table as the eligibility check; companies/[id] page already exists as the natural display surface.

Discovery — extending infrastructure that's already wired up

Natural-language search across the ecosystem LLM plumbing already exists platform-wide

Inspired by LinkedIn's conversational search, Upwork's AI job matching

Ecosystem Search today is keyword/ILIKE matching over platform_search_index. Every app already has a working connection to an LLM provider (the same llm_providers/llm_feature_flags infrastructure powering AI quality scoring) — routing a search query through it first to extract structured filters ("senior React freelancers, available this month, 4+ verified outcomes") before hitting the existing view is additive, not a new integration.

llm_providers (048_ai_quality_scores.sql) — no new AI vendor integration needed, just a new prompt against infrastructure already in production.

"Worked together" / shared-project discovery Data already exists, just not surfaced

Inspired by LinkedIn's alumni tool

StackEdge's project_applications and FreeAgent's gig_orders already record exactly who worked with whom. Surfacing "people you've worked with" as a follow-suggestion source on the People/Members pages turns data that already exists into a real network-growth loop, the same way LinkedIn's alumni tool turns a shared employer into a connection prompt.

Existing project_applications/gig_orders tables; the new user_follows table as the destination.

Lower priority — real gaps, but narrower audience or bigger lift

Hourly contracts with time tracking Genuinely new contract type

Inspired by Upwork's Work Diary

FreeAgent's gigs schema (price_min/max, delivery_days) is fixed-price/package-shaped by design, not hourly. Worth flagging as a deliberate scope choice rather than an oversight — only worth building if there's actual demand for hourly engagements, since it's a genuinely new contract type and payment model, not an extension of the existing one.

Referral bonus tracking Extends an existing bridge

Inspired by LinkedIn/Indeed referral programs

The peer referral bridge (create_job_referral_notification, migration 040) already notifies a referred candidate — there's no tracking of outcomes for the referrer (did they get hired? does the referrer earn anything?). Worth a look once the endorsement/recommendation features above are in, since all three deepen the same "your network is your credential" loop.

If building one thing next

  1. Bookable mentor sessions — the single biggest gap-to-existing-asset ratio on this list; the badge already exists, the payment rails already exist, only the booking layer is missing
  2. Skill endorsements — cheapest to build now that the follow graph exists, and directly reinforces the platform's own "not a self-reported resume" positioning
  3. Salary benchmarking — a read-only aggregate over data already being collected, zero new write path

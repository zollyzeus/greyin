Every link that goes nowhere

A monorepo-wide sweep across all 6 apps for links pointing at routes that don't exist, routes with nothing pointing at them, and links that are simply wired wrong. Read-only — nothing here was changed.

Dead links: one systemic bug worth fixing first — every app's /notifications page renders the shared, ecosystem-wide notifications table as same-origin links, so a StackEdge notification about a job referral links to stackedge.greyin.net/jobs/{id}, which doesn't exist there. The rest are boilerplate: /terms//privacy missing across every signup page, plus a handful of dead footer/nav links concentrated in greyin-b2b and GreyMatters.

Unused routes: genuinely none. Three routes looked unreferenced on a first pass but all three turned out to be legitimate external entry points (a payment webhook, a legacy-URL redirect shim, a post-payment success page reached via string concatenation rather than a template literal) — confirmed, not just assumed.

Invalid links: one real one — a "Save Job" button on the b2b job page that looks clickable but does nothing at all, in a Server Component with no way to wire it. The nested-<Link> bug class from earlier this session was checked everywhere and doesn't recur. A handful of optional-chaining hrefs are inconsistent with their own surrounding guards but the underlying data can't actually be null today — worth a tidy-up, not a fire.

apps/greyin-b2b/src/app/jobs/[id]/page.tsx:117 — an async Server Component with no client JS available:

No onClick, no form attribute, not inside a <form> — a complete no-op, sitting directly between two working controls (Apply Now, Refer a Friend), so it reads as functional. The two other server-component buttons found outside a form elsewhere in the codebase both correctly use the HTML5 form="..." association attribute — this is the one instance that doesn't.

Nested <Link>/<a> — checked everywhere, zero recurrencesClean

A tag-depth scanner across every .tsx file in all 6 apps found no instance of the bug class fixed earlier this session on the job-listing card. That fix (apps/greyin-b2b/src/app/jobs/page.tsx) is confirmed still correct and hasn't regressed.

Optional-chaining hrefs inconsistent with their own surrounding guardsCosmetic, not live

Five spots interpolate an optionally-chained id into an href (gig.seller?.id, job.companies?.id ×2, app.jobs?.id, app.project_asks?.id, project?.id) while the surrounding markup treats the same field as nullable elsewhere on the page — so the pattern is inconsistent, even though every one of these is backed by a NOT NULL foreign key with an open SELECT policy on the parent table, meaning it can't actually resolve to /undefined today. Worth a consistency pass, not urgent.

Checked and clear: malformed template literals, stray ${'{}'}, double-slash concatenation, wrong-variable interpolation (one apparent hit turned out to be an intentional Next.js routing workaround, not a bug), destructive actions wired as GET instead of POST, and forms with no action (all intentional same-page GET submits).

Suggested fix order

  1. Shared /notifications link rendered same-origin across all 5 apps — the one systemic bug, and the highest-traffic one
  2. /tags/{'{tag}'} — every tag chip on every published GreyMatters post 404s
  3. /about in GreyMatters' site-wide header nav — visible on every page
  4. "Save Job" no-op button on the b2b job detail page
  5. /terms / /privacy across all 5 signup pages, plus b2b's 4 dead footer links
  6. Optional-chaining href consistency pass (lowest priority — not currently reachable)
